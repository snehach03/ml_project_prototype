# BehaviorSense - AI-based behavioural stress & cognitive-workload estimation (research prototype)

Estimates how a person's current computer-interaction pattern compares with **their own usual pattern**, using a model
trained on the SWELL-KW dataset, explained with SHAP, served by FastAPI + WebSockets and shown in a React dashboard.

> **Not a diagnosis.** Predictions are experimental estimates from a small study. See `documentation/privacy_and_limitations.md`.

## What the model can and cannot do (real, reproducible numbers)

Leave-one-subject-out validation (25 folds, no participant in both train and test), evaluated per labelled block (75 blocks):

| Target | Best model | Block ROC-AUC (95% CI) | Block F1 | Verdict |
|---|---|---|---|---|
| Stress above own mean | SVM (RBF) | **0.687** (0.56 - 0.80) | 0.683 | weak but detectable signal (permutation p = 0.002) |
| Mental effort above own mean | Logistic Regression | 0.590 (0.43 - 0.74) | 0.595 | **no reliable signal** (p = 0.106); shown in the UI as "not reliable" |

Baselines on the same blocks: majority class accuracy 0.533 (AUC 0.5); stress model accuracy 0.653.
Full tables, confusion matrices and ROC curves: `documentation/model_evaluation_report.md` (generated by `python -m ml.train`).
Model selection used the same LOSO scores that are reported, so the winner's number is slightly optimistic. Hyper-parameters were fixed, not tuned.

## Quick start (Python 3.12, Node 20+)
```bash
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                      # defaults use SQLite, no database needed

# (optional) reproduce the model: ~1-2 min
python -m ml.train          # LOSO for 4 models x 2 targets, writes models/ and the evaluation report
python -m ml.explain        # global SHAP figure + models/shap_global.json (~1 min)

uvicorn backend.app.main:app --reload --port 8000         # run from the project root
# open http://localhost:8000  (serves the prebuilt frontend/dist), API docs at /docs
```
Frontend development with hot reload:
```bash
cd frontend && npm install && npm run dev                  # http://localhost:5173, proxies /api and /ws to :8000
npm run build                                              # refresh frontend/dist
```
PostgreSQL: set `DATABASE_URL=postgresql://user:pass@host:5432/dbname` in `.env`; tables are created at start-up.

## Demo without waiting 15 minutes
A first estimate needs 5 minutes of activity and, without earlier sessions, 14 minutes to form a provisional baseline.
To see the whole dashboard quickly, replay REAL dataset minutes (a research participant's, not yours) through the live API:
```bash
MIN_METRIC_INTERVAL_SECONDS=0 uvicorn backend.app.main:app --port 8000
python scripts/replay_demo.py --participant 7 --sessions 2 --client-id client_demo_replay_0001
```
Then, in the browser console on the dashboard: `localStorage.setItem("behaviorsense_client_id","client_demo_replay_0001")` and reload.

## How it works
1. **Cleaning** (`ml/preprocessing.py`): remove 999 failure markers and `#VALUE!`, drop relax minutes, join labels.
2. **Windows** (`ml/features.py`): 5 consecutive minutes -> 19 features (typing volume/variability, correction ratio, special/space/arrow rates, mouse activity/distance and their variability, clicks, scroll, drags, app/tab switches, active share, trends).
3. **Personal baseline**: every feature is z-scored against that person's own history. The same code runs in training and live.
4. **Models**: Logistic Regression, Random Forest, XGBoost, SVM with winsorising/scaling, class weighting, fixed hyper-parameters.
5. **Explainability** (`ml/explain.py`): SHAP (Tree/Linear/Kernel chosen by model type); the API returns the 5 behaviours that moved the latest estimate most, in plain language.
6. **Live app**: the browser tracker emits one object of counters per minute -> API validates, stores, scores with the real model -> pushes the result over WebSocket.

Browser events approximate the uLog counters: `mouse_act` = movement bursts (>250 ms gap), `wheel` = scroll bursts, `app_changes` = window blur, `tab_changes` = page hidden; only this tab is visible, whereas uLog logged the whole PC.

## Deploy on Render
`render.yaml` defines a Postgres database, the API (Python web service) and the static frontend. Replace the two placeholder URLs, then
*New > Blueprint*. Free-tier limits (cold starts, database expiry, RAM for SHAP) apply; check Render's current plans.

## Known gaps (please read)
- Authentication is only an anonymous per-browser id; add real accounts before any real deployment.
- Verified here: ML pipeline, 9 backend tests (SQLite), 4 tracker tests (jsdom), production frontend build, and an end-to-end run of the real server with replayed data. **Not verified here:** PostgreSQL itself, the Render deployment, and the UI in a real browser (layout/visual QA, real mouse/keyboard tracking) - please try these on your machine.
- Retrain (`python -m ml.train`) if you change scikit-learn/XGBoost versions, because the models are pickles.
